## 3-1. API URL이 두 곳에서 다르게 관리됨 (중요도: 높음)

### 문제

`src/user_js/user_song.js`에서 API URL을 직접 하드코딩하고, `src/user_js/user_request.js`에서 API_BASE를 다시 선언하고 있어요.

- `src/user_js/user_song.js` 119번째 줄, 133번째 줄
- `src/user_js/user_request.js` 1번째 줄

### 해결 방법

**Step 1.** HTML에서 `api-config.js`를 먼저 로드하세요.

```html
<!-- 수정 전 (woohyun/user_song.html 172번째 줄 근처) -->
    <script src="../src/user_js/theme.js"></script>
    <script src="../src/user_js/user_song.js"></script>

<!-- 수정 후 -->
    <script src="../src/api-config.js"></script>
    <script src="../src/user_js/theme.js"></script>
    <script src="../src/user_js/user_song.js"></script>
```

```html
<!-- 수정 전 (woohyun/user_request.html 160~161번째 줄) -->
    <script src="../src/user_js/theme.js"></script>
    <script src="../src/user_js/user_request.js"></script>

<!-- 수정 후 -->
    <script src="../src/api-config.js"></script>
    <script src="../src/user_js/theme.js"></script>
    <script src="../src/user_js/user_request.js"></script>
```

**Step 2.** `src/user_js/user_song.js`에서 하드코딩된 URL을 `API_BASE`로 교체하세요.

```js
// 수정 전 (src/user_js/user_song.js 119번째 줄)
    const res = await fetch('https://api.fullstackfamily.com/api/rawbeef/v1/categories');

// 수정 후
    const res = await fetch(`${API_BASE}/categories`);
```

```js
// 수정 전 (src/user_js/user_song.js 133번째 줄)
    const url = categoryId ? `https://api.fullstackfamily.com/api/rawbeef/v1/categories/${categoryId}` : 'https://api.fullstackfamily.com/api/rawbeef/v1/songs';

// 수정 후
    const url = categoryId ? `${API_BASE}/categories/${categoryId}` : `${API_BASE}/songs`;
```

**Step 3.** `src/user_js/user_request.js`에서 중복 선언을 제거하세요.

```js
// 수정 전 (src/user_js/user_request.js 1~2번째 줄)
const API_BASE = 'https://api.fullstackfamily.com/api/rawbeef/v1/requests';
const LIMIT = 30;

// 수정 후
const REQUEST_API = `${API_BASE}/requests`;
const LIMIT = 30;
```

그리고 이 파일 전체에서 `API_BASE`를 `REQUEST_API`로 바꿔야 해요. 찾기-바꾸기(Ctrl+H)로 한 번에 바꿀 수 있어요.

> **쉽게 말하면:** 전화번호부를 한 곳에만 두고 모두가 그걸 보는 거예요. 전화번호가 바뀌면 전화번호부 한 곳만 고치면 되니까요.

## 3-2. 테마 저장 방식이 관리자/사용자에서 다름 (중요도: 높음)

### 문제

`soyu/header.js` 36번째 줄에서 `sessionStorage`를, `src/user_js/theme.js` 17번째 줄에서 `localStorage`를 사용하고 있어요.

### 해결 방법

**Step 1.** `soyu/header.js`에서 `sessionStorage`를 `localStorage`로 바꾸세요.

```js
// 수정 전 (soyu/header.js 36번째 줄)
      sessionStorage.setItem('theme', 'dark');

// 수정 후
      localStorage.setItem('theme', 'dark');
```

```js
// 수정 전 (soyu/header.js 41번째 줄)
      sessionStorage.setItem('theme', 'light');

// 수정 후
      localStorage.setItem('theme', 'light');
```

```js
// 수정 전 (soyu/header.js 45번째 줄)
  applyTheme(sessionStorage.getItem('theme') !== 'light');

// 수정 후
  const saved = localStorage.getItem('theme');
  const prefersDark = window.matchMedia('(prefers-color-scheme: dark)').matches;
  applyTheme(saved ? saved === 'dark' : prefersDark);
```

> **쉽게 말하면:** `sessionStorage`는 포스트잇(임시), `localStorage`는 노트(영구)예요. 다크모드 같은 사용자 설정은 노트에 적어야 다음에도 기억해요.

## 3-3. 댓글 없는 신청에서 삭제 버튼 클릭 시 오류 (중요도: 높음)

### 문제

`soyu/admin_request.js` 113~119번째 줄에서 `req.comment`가 `null`일 때 삭제 버튼을 누르면 오류가 발생해요.

### 해결 방법

**Step 1.** 등록 버튼과 삭제 버튼을 댓글 유무에 따라 조건부로 생성하세요.

```js
// 수정 전 (soyu/admin_request.js 103~125번째 줄)
    const btnGroup = document.createElement('div');
    btnGroup.className = 'flex space-x-6 shrink-0';

    const registerBtn = document.createElement('button');
    registerBtn.className = 'hover:text-blue-600 font-black text-lg hover:scale-125';
    registerBtn.textContent = '등록';

    const deleteBtn = document.createElement('button');
    deleteBtn.className = 'hover:text-red-600 font-black text-lg hover:scale-125';
    deleteBtn.textContent = '삭제';
    deleteBtn.addEventListener('click', async () => {
      if (confirm('이 댓글을 정말 삭제할까요?')) {
        await deleteComment(req.comment.id);
        alert('삭제가 완료되었습니다!');
        await loadRequests();
      }
    });

    const requestDeleteBtn = document.createElement('button');
    requestDeleteBtn.className = 'hover:text-red-600 font-black text-xl absolute top-4 right-4 hover:scale-125 ';
    requestDeleteBtn.textContent = '✘';

    btnGroup.append(registerBtn, deleteBtn);

// 수정 후
    const btnGroup = document.createElement('div');
    btnGroup.className = 'flex space-x-6 shrink-0';

    // 댓글이 없을 때만 등록 버튼 표시
    if (!req.comment) {
      const registerBtn = document.createElement('button');
      registerBtn.className = 'hover:text-blue-600 font-black text-lg hover:scale-125';
      registerBtn.textContent = '등록';
      registerBtn.addEventListener('click', async () => {
        const message = adminInput.value;
        if (!message) {
          alert('내용이 입력되지 않았습니다!');
          return;
        }
        await saveComment(req.id, message);
        alert('등록이 완료되었습니다!');
        await loadRequests();
      });
      btnGroup.appendChild(registerBtn);
    }

    // 댓글이 있을 때만 삭제 버튼 표시
    if (req.comment) {
      const deleteBtn = document.createElement('button');
      deleteBtn.className = 'hover:text-red-600 font-black text-lg hover:scale-125';
      deleteBtn.textContent = '삭제';
      deleteBtn.addEventListener('click', async () => {
        if (confirm('이 댓글을 정말 삭제할까요?')) {
          await deleteComment(req.comment.id);
          alert('삭제가 완료되었습니다!');
          await loadRequests();
        }
      });
      btnGroup.appendChild(deleteBtn);
    }

    const requestDeleteBtn = document.createElement('button');
    requestDeleteBtn.className = 'hover:text-red-600 font-black text-xl absolute top-4 right-4 hover:scale-125 ';
    requestDeleteBtn.textContent = '✘';
```

**Step 2.** 기존 133~150번째 줄의 `registerBtn` 이벤트 리스너는 삭제하세요. (위 코드에서 이미 이벤트를 등록했으니까요)

```js
// 삭제할 코드 (soyu/admin_request.js 133~150번째 줄)
    registerBtn.addEventListener('click', async () => {
      // ... 이 전체 블록을 삭제
    });
```

> **쉽게 말하면:** 답변이 아직 없으면 "등록" 버튼만 보여주고, 답변이 있으면 "삭제" 버튼만 보여주는 거예요. 없는 답변을 삭제하려는 상황 자체를 막아버리는 거죠.

### 해결 방법

**Step 1.** 공통 유틸리티 파일을 새로 만드세요.

새 파일: `src/user_js/utils.js`

```js
/**
 * HTML 이스케이프 — XSS 공격 방지
 * 사용자 입력을 innerHTML에 넣기 전에 반드시 이 함수로 감싸세요.
 */
function esc(str) {
  return String(str)
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#39;');
}
```

**Step 2.** 기존 두 파일에서 `esc()` 함수 정의를 삭제하세요.


**Step 3.** HTML에서 `utils.js`를 다른 JS보다 먼저 로드하세요.

## 3-9. 헤더/푸터 렌더링 방식이 다름 (중요도: 중간)

### 문제

- `soyu/header.js` → `createElement` 방식 (코드 길지만 안전)
- `src/user_js/user_header.js` → `innerHTML` 방식 (코드 짧지만 주의 필요)

### 해결 방법

이건 팀에서 **하나의 방식으로 합의**하면 됩니다. 두 방식 다 장단점이 있어요.

**방식 A: innerHTML 통일 (추천 — 간결하고 읽기 쉬움)**

관리자 헤더도 innerHTML 방식으로 바꾸는 예시:

```js
// soyu/header.js — innerHTML 방식으로 변경
function createHeader() {
  const div = document.createElement('div');
  div.innerHTML = `
    <div class="flex justify-between items-center px-8 py-4 bg-gray-100 dark:bg-gray-900 border-b border-black/10 dark:border-white/10 h-[57px]">
      <span class="text-xl font-black bg-gradient-to-r from-cyan-400 to-purple-500 bg-clip-text text-transparent">TJ</span>
      <button id="themeToggle" class="text-sm text-gray-500 dark:text-gray-400 border border-black/10 dark:border-white/10 px-4 py-1.5 rounded-full hover:border-cyan-400 hover:text-cyan-400 transition-colors cursor-pointer">
        <span id="themeIcon">🌙</span>
        <span id="themeLabel">다크모드</span>
      </button>
    </div>
  `;
  return div.firstElementChild;
}
```

**방식 B: 둘 다 가능하되 규칙 정하기**

- 정적 HTML (변하지 않는 내용) → `innerHTML` OK
- 사용자 입력이 들어가는 동적 HTML → `createElement` 또는 `esc()` 필수

> **쉽게 말하면:** 팀 전체가 같은 도구를 쓰면 코드를 읽기 쉬워져요. 한 사람은 망치, 한 사람은 돌을 쓰면 헷갈리니까요.

## 3-11. 관리자 인증 토큰 만료 처리 없음 (중요도: 낮음)

### 문제

`soyu/admin_category.js`, `soyu/admin_song.js`, `soyu/admin_request.js`의 API 호출에서 토큰 만료(401) 응답을 처리하지 않아요.

### 해결 방법

이건 나중에 시간이 될 때 하면 돼요. 급하지 않아요!

모든 API 호출 함수에서 `res.status === 401`을 체크하는 패턴을 추가하면 돼요.

**예시 — `soyu/admin_category.js`의 `loadCategories` 함수:**

```js
// 수정 전 (soyu/admin_category.js 11~14번째 줄)
    if (!res.ok) {
      alert('카테고리 불러오기에 실패했습니다.');
      return;
    }

// 수정 후
    if (res.status === 401) {
      alert('로그인이 만료되었습니다. 다시 로그인해주세요.');
      localStorage.removeItem('adminToken');
      location.href = './admin_open.html';
      return;
    }
    if (!res.ok) {
      alert('카테고리 불러오기에 실패했습니다.');
      return;
    }
```

**팁:** `user_request.js`에서 이미 이 패턴을 잘 사용하고 있어요 (339번째 줄 등). 그 코드를 참고해서 관리자 쪽에도 적용하면 돼요.

> **쉽게 말하면:** 도서관 카드가 만료됐을 때 "카드가 만료됐어요, 다시 발급받으세요"라고 안내하는 것과 같아요.
