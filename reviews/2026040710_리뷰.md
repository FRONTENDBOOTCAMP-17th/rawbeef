## 2. 잘한 점

### API 연동 성공!
- 이전에는 LocalStorage에 데이터를 저장했는데, 이제 **실제 API 서버**와 통신하고 있어요. `fetch()` + `async/await`를 사용한 비동기 처리가 잘 되어 있어요. 첫 프로젝트에서 API 연동까지 해낸 것은 정말 대단해요!
- 카테고리 CRUD, 노래 CRUD, 신청 관리, 댓글 등록/삭제까지 모든 API를 연결했어요.

### 컴포넌트 분리 시작
- `sidebar.js`와 `header.js`로 반복되는 UI를 분리한 것은 훌륭한 첫 걸음이에요!
- 특히 `sidebar.js`에서 현재 페이지를 자동 감지해서 active 스타일을 적용하는 부분이 세심해요:
  ```js
  const currentPage = './' + location.pathname.split('/').pop();
  // ...
  const isActive = currentPage === item.href;
  ```

### 다크모드 구현
- Tailwind의 `dark:` 변형을 활용해서 다크모드를 구현했어요. `@custom-variant dark`로 수동 다크모드 전환도 설정되어 있어요.
- 관리자 페이지는 `sessionStorage`, 사용자 페이지는 `localStorage`로 테마를 저장하고 있어요.

### 사용자 페이지 완성도가 높아요
- `user_request.js`에서 **입력 검증**(제목 50자, 내용 300자, 비밀번호 4~10자)이 꼼꼼해요.
- 아코디언 UI, 페이지네이션, 관리자/일반 사용자 분기 처리가 잘 되어 있어요.
- `user_song.js`에서 카테고리 탭 필터링 + 검색 기능이 잘 동작해요.

### 코드 정리
- 사용하지 않는 `woohyun/Temporary/` 폴더와 `user_request2.html`을 삭제해서 프로젝트가 깔끔해졌어요!
- `.gitignore`에 `woohyun/Temporary`를 추가한 것도 좋아요.

### 인증 처리
- `admin_open.html`에 로그인 기능이 구현되었어요.
- 다른 관리자 페이지에서 토큰 없으면 로그인 페이지로 리다이렉트하는 가드(guard)도 있어요.
- 로그아웃 버튼도 사이드바에 잘 추가되었어요.

## 3. 개선하면 좋을 점

### 3-1. innerHTML에 사용자 입력을 넣으면 XSS 공격에 취약해요 (중요도: 높음)

**현재 상태:** `user_request.js`의 `renderList()`에서 서버에서 받은 데이터를 `innerHTML`에 직접 넣고 있어요.

```js
// user_request.js — renderList() 안
el.innerHTML = `
  <span class="text-sm font-medium ...">${item.title}</span>
  ...
  <p class="text-sm ...">${item.content}</p>
  ...
  <p class="text-sm ...">${item.comment.content}</p>
`;
```

**왜 개선하면 좋을까?**
만약 누군가 제목에 `<script>alert('해킹!')</script>` 같은 코드를 입력하면, 그 코드가 실제로 실행돼요. 이걸 **XSS(Cross-Site Scripting) 공격**이라고 해요. 방문하는 모든 사용자의 브라우저에서 악성 코드가 실행될 수 있어서 매우 위험해요.

`user_song.js`의 `renderChart()`에서도 `s.title`, `s.artist`를 innerHTML에 직접 넣고 있어요.

**추천:** 사용자가 입력한 텍스트는 반드시 **이스케이프(escape)** 처리해주세요.

```js
// 간단한 이스케이프 함수
function escapeHtml(text) {
  const div = document.createElement('div');
  div.textContent = text;
  return div.innerHTML;
}

// 사용 예시
el.innerHTML = `
  <span>${escapeHtml(item.title)}</span>
  <p>${escapeHtml(item.content)}</p>
`;
```

### 3-2. API URL이 모든 파일에 흩어져 있어요 — 결합도 문제 (중요도: 높음)

**현재 상태:** 같은 API 주소가 여러 파일에 반복되고 있어요.

```js
// admin_category.html 안에서
fetch('https://api.fullstackfamily.com/api/rawbeef/v1/categories')
fetch(`https://api.fullstackfamily.com/api/rawbeef/v1/categories/${id}`)
fetch(`https://api.fullstackfamily.com/api/rawbeef/v1/categories/${id}/move-up`)

// admin_song.html 안에서
fetch('https://api.fullstackfamily.com/api/rawbeef/v1/songs')
fetch(`https://api.fullstackfamily.com/api/rawbeef/v1/songs/${id}`)

// admin_request.html 안에서
fetch('https://api.fullstackfamily.com/api/rawbeef/v1/requests')
fetch(`https://api.fullstackfamily.com/api/rawbeef/v1/requests/${id}/comments`)
```

반면, `user_request.js`에서는 이미 잘 하고 있어요:
```js
const API_BASE = 'https://api.fullstackfamily.com/api/rawbeef/v1/requests';
```

**왜 개선하면 좋을까?**
이것은 **"결합도(Coupling)가 높다"**는 전형적인 예시예요. API 주소가 바뀌면 (예: 서버 이전, 버전 업) 모든 파일을 찾아다니며 수정해야 해요. 하나라도 빼먹으면 버그가 생기죠.

**추천:** API 기본 주소를 하나의 파일에서 관리하세요.

```js
// src/api-config.js (새 파일)
const API_BASE = 'https://api.fullstackfamily.com/api/rawbeef/v1';

// 각 파일에서 사용
fetch(`${API_BASE}/categories`)
fetch(`${API_BASE}/songs/${id}`)
```

### 3-3. 관리자 페이지의 JS가 HTML 안에 섞여 있어요 — 응집도 문제 (중요도: 높음)

**현재 상태:** `admin_category.html`(180줄), `admin_song.html`(270줄), `admin_request.html`(140줄)의 `<script>` 태그 안에 JavaScript가 직접 들어있어요.

```html
<!-- admin_category.html -->
<script>
  const token = localStorage.getItem('adminToken');
  // ... 180줄의 JavaScript 코드 ...
  loadCategories();
</script>
```

반면, 사용자 페이지는 잘 분리되어 있어요:
```html
<!-- woohyun/user_request.html -->
<script src="../src/user_js/user_request.js"></script>
```

**왜 개선하면 좋을까?**
이것은 **"응집도(Cohesion)가 낮다"**는 전형적인 예시예요. 하나의 파일에 HTML(화면 구조)과 JS(동작 로직)가 섞여 있으면:
- HTML을 수정할 때 실수로 JS를 건드릴 수 있어요.
- JS 코드만 찾아보기 어려워요.
- 코드 에디터의 자동완성 기능이 잘 동작하지 않아요.

**추천:** 사용자 페이지처럼 JS를 별도 파일로 분리하세요.

```
soyu/
├── admin_category.html     ← HTML만
├── admin_category.js       ← JS만 (새 파일)
├── admin_song.html
├── admin_song.js           ← 새 파일
├── admin_request.html
└── admin_request.js        ← 새 파일
```

### 3-7. token을 매번 다시 꺼내고 있어요 — 응집도 문제 (중요도: 중간)

**현재 상태:** 같은 파일 안에서 `localStorage.getItem('adminToken')`을 여러 번 호출해요.

```js
// admin_category.html — 파일 맨 위에서 한 번
const token = localStorage.getItem('adminToken');

// saveCategory() 안에서 또
const token = localStorage.getItem('adminToken');

// editCategory() 안에서 또
const token = localStorage.getItem('adminToken');

// moveCategoryUp() 안에서 또
const token = localStorage.getItem('adminToken');

// deleteCategory() 안에서 또
const token = localStorage.getItem('adminToken');
```

반면, `user_request.js`에서는 이미 잘 하고 있어요:
```js
function getAdminToken() {
  return localStorage.getItem('adminToken');
}
```

**왜 개선하면 좋을까?**
`'adminToken'`이라는 문자열이 잘못 타이핑되면 버그가 생겨요 (예: `'amdinToken'`). 이것도 **결합도** 문제예요 — 토큰 키 이름이 바뀌면 모든 곳을 수정해야 해요.

**추천:** `user_request.js`처럼 함수로 만들거나, 파일 상단에 상수로 정의하세요.

### 3-8. `<label>`에 `maxlength` 속성이 있어요 — 잘못된 HTML (중요도: 중간)

**현재 상태:** `admin_song.html`의 모달 폼이에요.

```html
<label for="titleInput" class="block font-black mb-1" maxlength="50">제목</label>
<label for="artistInput" class="block font-black mb-1" maxlength="50">가수</label>
<label for="scoreInput" class="block font-black mb-1" min="1" max="999">SCORE</label>
```

**왜 개선하면 좋을까?**
`maxlength`, `min`, `max`는 `<input>` 태그에 넣어야 하는 속성인데, `<label>` 태그에 들어가 있어요. `<label>`에는 이 속성들이 아무 효과가 없어요. 제목 입력란에 50자 제한을 걸고 싶었다면, `<input>`에 넣어야 해요.

**추천:**
```html
<label for="titleInput" class="block font-black mb-1">제목</label>
<input type="text" id="titleInput" maxlength="50" class="w-full border-2 ..." />
```

### 3-9. 에러 처리가 일부 함수에만 되어 있어요 (중요도: 중간)

**현재 상태:** `admin_category.html`에서 일부 함수에는 `try/catch`가 있고, 일부에는 없어요.

```js
// ✅ try/catch가 있음
const saveCategory = async (title) => {
  try {
    const res = await fetch(...);
    // ...
  } catch {
    alert('카테고리 저장에 실패했습니다.');
  }
};

// ❌ try/catch가 없음 — 네트워크 오류 시 페이지가 멈춤
const editCategory = async (id, newTitle) => {
  const res = await fetch(...);
  const json = await res.json();
  return json.data;
};

// ❌ try/catch가 없음
const moveCategoryUp = async (id) => {
  await fetch(...);
  await loadCategories();
};
```

**왜 개선하면 좋을까?**
인터넷이 끊기거나 서버에 문제가 생기면, `try/catch`가 없는 함수는 에러가 처리되지 않아서 페이지가 멈출 수 있어요. 사용자는 무슨 일이 일어났는지 알 수 없게 되죠.

**추천:** API를 호출하는 모든 `async` 함수에 `try/catch`를 넣어주세요.

### 3-10. 테마 저장 방식이 관리자/사용자 페이지에서 달라요 (중요도: 중간)

**현재 상태:**

```js
// soyu/header.js — 관리자 페이지
sessionStorage.setItem('theme', 'dark');   // sessionStorage 사용

// src/user_js/theme.js — 사용자 페이지
localStorage.setItem('theme', 'dark');     // localStorage 사용
```

**왜 개선하면 좋을까?**
- `sessionStorage`는 **탭을 닫으면 사라져요**. 관리자가 다크모드로 설정해도 탭을 닫으면 초기화돼요.
- `localStorage`는 **탭을 닫아도 유지돼요**. 사용자 설정은 유지되죠.
- 같은 프로젝트에서 두 가지 방식을 쓰면 혼란스러워요.

**추천:** 둘 다 `localStorage`로 통일하세요. 테마 설정은 브라우저를 닫아도 유지되는 게 자연스러워요.
