## 테일윈드 미적용 원인 분석 및 수정

### 원인 1: `vite.config.js`에 존재하지 않는 함수 사용
PR에서 `vite.config.js`에 추가한 코드:
```js
index: path.resolve(__dirname, 'index.html'),
...findAllHtmlFiles(path.resolve(__dirname, 'src')),
...findAllHtmlFiles(path.resolve(__dirname, 'soyu')),
```
- `path`는 모듈로 import되지 않음 (기존에는 `import { resolve } from 'path'`로 destructure됨)
- `findAllHtmlFiles` 함수가 정의되어 있지 않음
- 결과: Vite 실행 시 에러 발생 → soyu HTML 파일이 Vite entry point로 등록되지 않음 → Tailwind CSS 처리 불가

### 수정 내용
`vite.config.js`에서 soyu HTML 파일들을 명시적으로 등록:
```js
admin_open: resolve(__dirname, 'soyu/admin_open.html'),
admin_category: resolve(__dirname, 'soyu/admin_category.html'),
admin_song: resolve(__dirname, 'soyu/admin_song.html'),
admin_request: resolve(__dirname, 'soyu/admin_request.html'),
```

### 원인 2: Tailwind CSS 작동 원리 이해
이 프로젝트는 **Tailwind CSS v4** + `@tailwindcss/vite` 플러그인을 사용합니다.
- `src/style.css`에 `@import 'tailwindcss';`가 선언되어 있음
- HTML 파일이 Vite의 rollup input에 등록되어야 `<link rel="stylesheet" href="../src/style.css" />`가 Vite를 통해 처리됨
- Vite가 CSS를 처리할 때 `@tailwindcss/vite` 플러그인이 Tailwind 클래스를 자동으로 생성
- HTML 파일이 entry point로 등록되지 않으면 Vite가 해당 파일을 처리하지 않아 Tailwind가 적용되지 않음

## 기존 문제 (이 PR과 무관)
- `index.html`에서 `<script type="module" src="/main.js">`로 참조하지만, 실제 파일은 `src/main.js`에 위치 → 빌드 시 에러 발생
- 이 문제는 별도로 수정이 필요함
