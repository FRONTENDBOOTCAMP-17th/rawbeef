## 총평

이번 변경에는 좋은 방향이 분명히 있습니다. 소개 페이지의 스크립트를 `SWcantabile_introduce.js`와 `SWcantabile_introduce_bg.js`로 나누려 한 점, 반응형 클래스를 일부 도입한 점, 파비콘을 공통으로 붙인 점은 모두 좋아졌습니다.

다만 실제 서비스 관점에서는 "화면은 바뀌었는데 기본 동작이 조용히 깨지는 문제"가 함께 들어왔습니다. 특히 소개 페이지의 테마 스크립트 실행 시점, 실시간 점수 표시, 관리자 성공 안내 문구는 사용자가 바로 체감하는 회귀 버그입니다.

또한 팀 규칙인 "CSS는 최소화하고 Tailwind CSS를 우선 사용"이라는 기준에서는 아직 아쉬움이 남습니다. 소개 페이지 한 파일에 스타일과 구조가 같이 몰려 있어 응집도는 충분히 높지 않고, 공통 헤더 재사용이 빠지면서 결합도도 다시 높아졌습니다.

## 1. 반드시 먼저 고쳐야 하는 문제

### 1.1 소개 페이지에서 `theme.js`가 너무 일찍 실행되어 자바스크립트 오류가 날 수 있습니다

- 위치:
  - `src/SWcantabile/SWcantabile_introduce.html:59`
  - `src/component/theme.js:3-23`

현재 소개 페이지는 `<head>` 안에서 바로 `theme.js`를 불러옵니다.

그런데 `theme.js`는 실행되자마자 아래 요소를 찾습니다.

- `#themeToggle`
- `#themeIcon`
- `#themeLabel`

문제는 이 시점에는 아직 `<body>`가 만들어지지도 않았고, 이번 변경에서는 소개 페이지에서 공통 헤더 자체도 렌더링하지 않고 있다는 점입니다. 그래서 `icon.textContent`, `label.textContent`를 실행하는 순간 `null` 오류가 발생할 수 있습니다.

이 문제가 위험한 이유는 다음과 같습니다.

- 테마 적용이 실패합니다.
- 콘솔에 오류가 발생합니다.
- "공통 스크립트는 어느 페이지에서나 안전하게 돌아가야 한다"는 원칙이 깨집니다.

공통 기능일수록 "이 페이지에 해당 요소가 없을 수도 있다"는 상황을 항상 고려해야 합니다.

### 1.2 "실시간 점수" 숫자가 계속 숨겨져 있어서 핵심 정보가 보이지 않습니다

- 위치:
  - `src/SWcantabile/SWcantabile_introduce.html:228-230`
  - `src/SWcantabile/SWcantabile_introduce.js:17-22`

`#topSongScore`에는 여전히 `hidden` 클래스가 들어 있습니다.

하지만 데이터를 불러온 뒤 자바스크립트에서는:

- 텍스트만 넣고
- `hidden`은 제거하지 않습니다

그래서 API 호출이 성공해도 사용자는 점수 숫자를 볼 수 없습니다.

이런 문제는 초보 개발자에게 특히 중요합니다.  
"데이터를 잘 가져왔다"와 "사용자 화면에 잘 보인다"는 전혀 다른 문제이기 때문입니다.

이번 섹션 이름이 "실시간 점수"인데 가장 중요한 숫자가 안 보이면, 기능은 사실상 반쯤 고장 난 상태라고 봐야 합니다.

### 1.3 관리자 카테고리 화면에서 실패해도 성공 안내가 뜰 수 있습니다

- 위치:
  - `src/admin/admin_category.js:169-177`
  - `src/admin/admin_category.js:189-198`

이번 변경에서 `saveCategory()`와 `editCategory()`는 실패 시 `null`을 반환하도록 바뀌었습니다. 방향은 좋습니다.

그런데 호출하는 쪽에서는 반환값을 확인하지 않고 바로:

- `loadCategories()`를 다시 실행하고
- "수정이 완료되었습니다", "등록이 완료되었습니다" 알림을 띄웁니다

삭제도 마찬가지로 `fetch()` 결과의 `res.ok`를 확인하지 않고 바로 "삭제가 완료되었습니다!"를 띄웁니다.

이렇게 되면 실제로는 실패했는데도 사용자에게는 성공처럼 보일 수 있습니다.

관리자 화면에서는 이런 안내 문구가 특히 중요합니다.

- 사용자는 정말 저장됐다고 믿고 다음 작업으로 넘어갑니다.
- 실제 데이터와 화면 안내가 달라집니다.
- 나중에 "왜 안 저장됐지?"를 추적하기 어려워집니다.

즉, 사용자 신뢰를 깨는 문제입니다.

## 2. 꼭 개선하면 좋은 문제

### 2.1 소개 페이지에서 공통 헤더 재사용이 빠지면서 구조 일관성이 깨졌습니다

- 위치:
  - `src/SWcantabile/SWcantabile_introduce.html:62-68`
  - `src/SWcantabile/SWcantabile_introduce.html:264-269`
  - `src/component/header.js:42-45`

이전 소개 페이지에는 `<div id="user-header"></div>`가 있었고, `header.js`를 통해 공통 헤더를 붙일 수 있는 구조였습니다. 이번 변경에서는 그 연결이 사라졌습니다.

이 문제는 단순히 "헤더가 보이냐"의 문제가 아닙니다.

- 다른 사용자 페이지와 화면 구조가 달라집니다.
- 공통 수정이 소개 페이지에는 자동으로 반영되지 않습니다.
- 페이지마다 예외가 생기면서 결합도가 높아집니다.

공통 컴포넌트는 한 번 연결해 두고 모두가 같이 쓰는 것이 가장 좋습니다.

### 2.2 소개 페이지에 일반 CSS가 아직 많이 남아 있어 Tailwind 중심 구조가 약합니다

- 위치: `src/SWcantabile/SWcantabile_introduce.html:10-58`

이번 변경으로 `glowOrb`, `#bg-canvas` 일부는 Tailwind 클래스로 옮긴 점이 좋았습니다. 하지만 여전히 소개 페이지 안에 `<style>` 블록이 크게 남아 있습니다.

현재 남아 있는 스타일 중 상당수는 아래처럼 구분할 수 있습니다.

- Tailwind로 옮기기 쉬운 것
  - 폰트 적용
  - 위치와 여백
  - 투명도
  - z-index
- CSS로 남겨도 되는 것
  - `::after` 같은 가상 요소
  - 복잡한 keyframe 또는 매우 특수한 효과

Tailwind 프로젝트에서 일반 CSS가 많아질수록:

- HTML만 보고 레이아웃을 파악하기 어려워지고
- 스타일 위치를 계속 왔다 갔다 해야 하며
- 페이지별 규칙이 따로 생겨 결합도가 높아집니다

지금 단계에서는 "Tailwind로 가능한 건 먼저 Tailwind로 보내기" 습관이 중요합니다.

### 2.3 푸터 템플릿에 잘못된 HTML 구조가 들어가 있습니다

- 위치: `src/SWcantabile/SWcantabile_footer.js:19-22`

아래처럼 `<p>` 안에 다시 `<p>`가 들어가 있습니다.

```html
<p>
  <span>...</span>
  <p>Copyright...</p>
</p>
```

HTML에서는 `<p>` 안에 다른 블록 요소 `<p>`를 넣는 것이 올바른 구조가 아닙니다. 브라우저가 자동으로 태그를 닫아 버릴 수 있어서, 화면이 "우연히" 맞아 보이더라도 언제든 배치가 달라질 수 있습니다.

이런 문제는 작은 것처럼 보여도 초보 개발자에게 중요합니다.  
"브라우저가 봐주니까 괜찮다"가 아니라 "문법이 맞는 구조를 만든다"는 습관이 필요합니다.

## 3. 좋은 점

- `src/SWcantabile/SWcantabile_introduce.js`를 새로 분리한 방향은 좋습니다. 소개 페이지 한 파일에 스크립트를 전부 넣는 것보다 응집도가 좋아졌습니다.

- 소개 페이지에 `sm:`, `lg:` 반응형 클래스를 도입한 것은 이전보다 훨씬 좋은 방향입니다.
